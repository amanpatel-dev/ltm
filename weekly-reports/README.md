# Weekly Reports

This folder is Group B’s **work record**: goals, commands, WSL/Hadoop notes, file syncs to `D:\LTM`, checks, outputs, errors, and next work. Detailed theory lives under [study-material](../study-material/README.md). Use the short [SIMPLE-WEEKLY-UPDATE.md](SIMPLE-WEEKLY-UPDATE.md) or the detailed [weekly report template](../docs/WEEKLY-REPORT-TEMPLATE.md).

The reporting style follows the same discipline as Group A’s Apache Giraph project weekly folder: factual evidence, honest incomplete work, and a Thursday meeting cycle. Content stays LTM-focused.

## Filename format

```text
YYYY-MM-DD-week-N.md
```

Use the Thursday meeting date (or the Friday that closes the work week) as `YYYY-MM-DD`.

## Each report must contain

- planned goal;
- concepts studied;
- completed work;
- Git commits, commands, datasets, and results;
- errors, causes, and verified fixes;
- individual contributions;
- supervisor feedback (when available);
- assigned work for the next Thursday.

Failed or incomplete work must be reported honestly. When a detail cannot be verified, label that detail as reported or awaiting evidence.

## Working rule for this repository

Whenever practical work is finished—even a small task—update the current week’s Markdown report in the same commit (or immediately after), so GitHub always shows what was done.
